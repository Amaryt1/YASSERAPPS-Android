# MOD-only catalogue
Only owner-reviewed modified releases with a public permission reference and evidence of modifications are accepted. Place authorized exports in this directory. Each JSON file contains source, permissionUrl, reviewedByOwner=true and apps. Each app requires id, name, packageName, category, version, versionCode, modified=true, modDescription, modEvidenceUrl, publisherUrl and optionally iconUrl/license. Evidence and permission must be reviewed by the owner; a boolean alone does not establish authenticity. No ordinary listings or unverified direct downloads are accepted. Empty catalogue is valid.

Arabic modification descriptions are required. To enable a direct install, include an authorized HTTPS .apk URL, sizeBytes, sha256 and signerSha256 in each entry. Review the exact binary, permissions, license and provenance before publishing. Missing APK fields leave the listing non-installable. The device verifies the downloaded binary hash, package identity, signer and version before installation. Do not invent checksums or use unauthorized repackages.

## Authorized remote JSON API
Edit `catalog/mod-source-candidates.json` after receiving provider permission and the actual endpoint. Set `apiUrl`, `permissionUrl`, `authorizationConfirmed: true`, `enabled: true`, `itemsPath` (default `apps`), `nextPath` (default `next`, URL or null), and optionally `fields` mapping canonical keys to provider dot-paths. For private API keys, configure the matching GitHub Actions secret and set `tokenEnv` to its name; never commit the token. Arabic `modDescription` must be supplied or translated and reviewed before publishing. HTTPS only, same-origin pagination, no redirects, bounded pages and delay. On failure, publication stops and the prior catalog remains. Disabled sources make no network requests. Tests use mock data, not live provider endpoints.

Each candidate provider has an independent output API under `catalog/api/v1/sources/<slug>/index.json`. Its manifest exposes total, installable count, status and paginated app/game groups. The endpoints are generated even for disabled sources, with zero records and explicit awaiting status; no fabricated listings. These are YASSERAPPS output APIs, not upstream provider endpoints.

XML export: `catalog/api/v1/catalog.xml` holds the combined catalog. Each provider also gets `catalog/api/v1/sources/<slug>/catalog.xml`. XML includes the same approved names, images, Arabic descriptions, version fields, source page URLs and verified APK metadata as JSON. XML is round-trip parsed and record counts and IDs are checked at build time. Unavailable providers export an empty catalog with an explicit status.

Public capability probe: `catalog/probe_sources.py` checks robots policy, advertised sitemap/RSS/Atom/JSON documents, same-origin HTML link counts, JSON-LD and Open Graph. It is diagnostic only, honors denials, rate limits and crawl delays, and never fetches APKs or publishes unreviewed records. See the separate `Probe public MOD source capabilities` workflow artifact for measured results.
